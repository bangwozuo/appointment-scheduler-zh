# 排班调度师

使用同包 `scripts/product.py` 调用已安装员工的原生工作流，不自行创建调度、检查点、模型循环或发送连接器。

1. 先运行 `python scripts/product.py contract --connection <连接文件>`。准确安装与指纹不符就停止；不换员工、版本或目的地。当前客户端只连接本地8942服务。
2. 根据业务任务选择 `smart` 多资源排班、`notify` 预约通知草稿、`booking` 预约受理、`scheduling` 技师场地排班、`conflict` 冲突核对、`no_show` 爽约候补、`commission` 提成、`forecast` 客流或 `weekly` 周复盘。输入文件只含 `fields` 和任务原文 `text`；fields内含operation和data，遵守实际contract的输入规范。缺参数、设备或客户规则时展示缺项，不编造。
3. 新事项保留稳定编号，`submit --operation <原编号> --input <输入文件>`只提交一次。丢响应或状态不明时用 `lookup --operation <同编号>`查原事项，不能换号重发。
4. 展示真实来源、未排原因、约束复检和可编辑文件。通知按次日前一天15:00–16:00、到店前2小时或30分钟及明确静默/频控规则办理；不能将提前24小时当作前一天时间窗。知识引用的分类、许可引用和适用范围应保留。
5. 用 `review --decision revise --expected-revision <修订> --notes <意见>`保存意见；用户明确同意当前稿才confirm，退回则reject。确认后回读同一原稿与原生终态。

各命令均需 `--connection <连接文件>`。该文件不含凭证，不读取其他应用Cookie。当前入口使用明确合成资料，确认是本地成果接收；不表示创建真实预约、通知客户、支付工资、客户验收或经营收益。触发服务沿用原框架，本Skill不启动常驻时钟。当前DA框架已按本岗准确源码和安装取证；其他Host与外部连接仍按实际资格显示。

当前原生员工源1.1.0已将受理、技师排班、冲突核对接入共享排班能力。对应data使用当前入口examples的门店/快照/资源结构。爽约候补data含risk原评分输入、rotation候补/空位/本次明确时点及expected_ledger_revision；ledger由服务端从同门店同空位原稿读取，不可用客户端列表覆盖。sent/confirmed/declined是明确外部回执事实，不能从本地草稿确认推断；合成验收也必须标明合成。旧已完成事项可按原编号只读回顾，不能借旧安装续办新动作。

当前安装保留九项主资产、十二项知识及原业务属性。旧事项使用原编号只读回顾，旧门店已送达/占用记录继续参与新事项频控。原工作空间、会话及历史原件不迁移；确认是本地原稿接收。
